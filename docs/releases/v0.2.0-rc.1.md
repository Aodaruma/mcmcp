MCMCP 0.2 introduces public API v2: describe Minecraft tasks with coordinates, areas, and item counts, then let your assistant follow their progress or cancel them.

**Requires Minecraft Java Edition 26.2, NeoForge 26.2.0.59, and Java 25.** This is a client-side pre-release; no server-side MCMCP installation is needed.

## Upgrading from 0.1

API v2 replaces `agent_start_action` and the public JSON Action DSL. Restart your MCP client to refresh its tool list, and update existing workflows to use the new tools and scripts. Start with `PUBLIC_API.md` in the distribution ZIP.

## Added

- **A simpler set of 17 tools.** Ask your assistant to move, mine an area, place blocks, craft, manage items, or use game chat with dedicated tools. Actions share progress tracking, results, and cancellation. ([Issue #84](https://github.com/Aodaruma/mcmcp/issues/84), [PR #85](https://github.com/Aodaruma/mcmcp/pull/85))
- **Scripts and blueprints for longer tasks.** Combine actions in scripts with limits on time and work, or preview a JSON/CSV blueprint before building it in sections. ([Issue #84](https://github.com/Aodaruma/mcmcp/issues/84), [PR #85](https://github.com/Aodaruma/mcmcp/pull/85))
- **More backpack operations.** Inspect supported carried or equipped backpacks and move a specified number of items. Two backpacks of the same type can be selected separately. ([Issue #70](https://github.com/Aodaruma/mcmcp/issues/70), [PR #82](https://github.com/Aodaruma/mcmcp/pull/82))
- **A choice of recipe search scopes.** Search unlocked recipes only, or use the “all craftable recipes” mode to include additional recipes made available to the client. ([Issue #71](https://github.com/Aodaruma/mcmcp/issues/71), [PR #87](https://github.com/Aodaruma/mcmcp/pull/87))
- **Warp Stone destinations.** List available Waystones destinations, check experience costs, and select a destination using a supported Warp Stone. Check the player's destination after sending a selection. ([Issue #77](https://github.com/Aodaruma/mcmcp/issues/77), [PR #85](https://github.com/Aodaruma/mcmcp/pull/85))

## Improved

- **Smaller routine status responses.** The default view focuses on the player and nine hotbar slots. Request detailed inventory or other information when you need it. ([Issue #6](https://github.com/Aodaruma/mcmcp/issues/6), [Issue #84](https://github.com/Aodaruma/mcmcp/issues/84), [PR #85](https://github.com/Aodaruma/mcmcp/pull/85))
- **Easier observation updates.** Request the latest view in one call, and discard unused observation pages to free capacity. ([Issue #7](https://github.com/Aodaruma/mcmcp/issues/7), [Issue #10](https://github.com/Aodaruma/mcmcp/issues/10), [PR #89](https://github.com/Aodaruma/mcmcp/pull/89), [PR #88](https://github.com/Aodaruma/mcmcp/pull/88))
- **Levers that stay in the requested state.** Ask for ON or OFF without toggling a lever that is already set correctly. ([Issue #75](https://github.com/Aodaruma/mcmcp/issues/75), [PR #80](https://github.com/Aodaruma/mcmcp/pull/80))
- **Timed and repeated inputs.** Set hold durations and repeat counts for input steps. Detailed information about held items is available on request. ([Issue #34](https://github.com/Aodaruma/mcmcp/issues/34), [PR #35](https://github.com/Aodaruma/mcmcp/pull/35))
- **Separate connection settings for Minecraft profiles.** Generate isolated Codex settings, identify settings that refer to another profile, and get a prompt response if another process is updating the configuration. ([Issue #9](https://github.com/Aodaruma/mcmcp/issues/9), [PR #86](https://github.com/Aodaruma/mcmcp/pull/86))

## Fixed

- **Emergency Elytra landings on narrow banks.** Recovery now checks the space needed to land and stop, reducing cases where the player overshoots a dry landing area. ([Issue #91](https://github.com/Aodaruma/mcmcp/issues/91), [PR #93](https://github.com/Aodaruma/mcmcp/pull/93))
- **Repeated replanning near ladders.** Fixed movement between small platforms beside a ladder getting stuck because the planned path did not match the player's actual position. ([Issue #98](https://github.com/Aodaruma/mcmcp/issues/98), [PR #99](https://github.com/Aodaruma/mcmcp/pull/99))
- **Inputs remaining active after bow errors.** Cancelling or firing a bow now continues releasing owned inputs even if the operation encounters an error. ([Issue #90](https://github.com/Aodaruma/mcmcp/issues/90), [PR #85](https://github.com/Aodaruma/mcmcp/pull/85))
- **Recently returned observations becoming unavailable.** A view can still be read for its allowed lifetime when newer observations arrive. ([Issue #96](https://github.com/Aodaruma/mcmcp/issues/96), [PR #97](https://github.com/Aodaruma/mcmcp/pull/97))
- **Waiting for long-running actions.** The PowerShell client now keeps checking actions that are still running until the requested wait limit is reached. Reported failures, cancellations, and partial results are preserved. ([Issue #84](https://github.com/Aodaruma/mcmcp/issues/84), [PR #85](https://github.com/Aodaruma/mcmcp/pull/85))

## Documentation and limits

- **Updated v2 setup and API guides.** The distribution ZIP includes the mod JAR, illustrated setup guide, API guide, license, source information, and checksums. ([Issue #84](https://github.com/Aodaruma/mcmcp/issues/84), [PR #94](https://github.com/Aodaruma/mcmcp/pull/94), [PR #101](https://github.com/Aodaruma/mcmcp/pull/101))
- Backpack support is limited to the documented storage types and tested mod versions. Recipe search can be incomplete, and finding a recipe does not mean automatic crafting or material/workstation checks are supported. ([Issue #70](https://github.com/Aodaruma/mcmcp/issues/70), [Issue #71](https://github.com/Aodaruma/mcmcp/issues/71))
- Automatic recovery has time and distance limits and can still fail when additional hazards appear. Some ladder-to-platform transitions also remain unverified. ([Issue #91](https://github.com/Aodaruma/mcmcp/issues/91), [Issue #81](https://github.com/Aodaruma/mcmcp/issues/81))
- Connection setup diagnoses the selected configuration; it does not confirm that the AI client has connected. ([Issue #9](https://github.com/Aodaruma/mcmcp/issues/9))

See the [tested features and remaining work](https://github.com/Aodaruma/mcmcp/blob/v0.2.0-rc.1/docs/experiments/20261115_release_rc1.md) for the validation record.

MCMCP 0.2では公開API v2を導入しました。座標・範囲・個数を指定して作業を頼み、進行確認や取消を共通の方法で行えるようにしています。

**対象：Minecraft Java Edition 26.2 / NeoForge 26.2.0.59 / Java 25。** クライアント側専用のリリース候補です。サーバー側へのMCMCP導入は不要です。

### 0.1系から更新する方へ

`agent_start_action`と公開JSON Action DSLは、新しいツールとスクリプトへ置き換わります。更新後はMCPクライアントを再起動してツール一覧を読み直し、配布ZIPの`PUBLIC_API.md`を参考に既存の手順を移行してください。

### 追加した機能

- **作業ごとに使える17ツールへ整理。** 移動、範囲採掘、ブロック設置、クラフト、アイテム管理、ゲーム内チャットなどを専用ツールで頼めます。進行確認・結果取得・取消も共通化しました。（[Issue #84](https://github.com/Aodaruma/mcmcp/issues/84), [PR #85](https://github.com/Aodaruma/mcmcp/pull/85)）
- **長い作業向けのスクリプトと設計図。** 実行時間や作業量に上限を設けたスクリプトで複数の操作をまとめられます。JSON/CSVの設計図を事前確認し、区間ごとに施工することもできます。（[Issue #84](https://github.com/Aodaruma/mcmcp/issues/84), [PR #85](https://github.com/Aodaruma/mcmcp/pull/85)）
- **バックパックの内容確認・数量指定移送。** 対応する所持・装備中のバッグを開き、指定した個数を取り出したり収納したりできます。同じ種類のバッグを複数持っていても、個別に選択できます。（[Issue #70](https://github.com/Aodaruma/mcmcp/issues/70), [PR #82](https://github.com/Aodaruma/mcmcp/pull/82)）
- **レシピの検索範囲を選べる設定。** 「解放済みのレシピのみ」と「すべての作成可能なレシピ」を切り替え、クライアントへ提供された追加レシピも検索できます。（[Issue #71](https://github.com/Aodaruma/mcmcp/issues/71), [PR #87](https://github.com/Aodaruma/mcmcp/pull/87)）
- **ワープストーンの行き先選択。** 対応するWaystonesのワープストーンで、行き先と経験値費用を確認して選択できます。選択要求を送った後は、プレイヤーが到着したことを別途確認してください。（[Issue #77](https://github.com/Aodaruma/mcmcp/issues/77), [PR #85](https://github.com/Aodaruma/mcmcp/pull/85)）

### 改善した点

- **普段の状態確認をコンパクトに。** 既定ではプレイヤー情報と手元9枠を中心に返し、詳しい所持品などは必要なときに取得できるようにしました。（[Issue #6](https://github.com/Aodaruma/mcmcp/issues/6), [Issue #84](https://github.com/Aodaruma/mcmcp/issues/84), [PR #85](https://github.com/Aodaruma/mcmcp/pull/85)）
- **周囲の情報を取得しやすく。** 最新の観測を1回で取得でき、使わなくなった観測ページも破棄して空きを確保できます。（[Issue #7](https://github.com/Aodaruma/mcmcp/issues/7), [Issue #10](https://github.com/Aodaruma/mcmcp/issues/10), [PR #89](https://github.com/Aodaruma/mcmcp/pull/89), [PR #88](https://github.com/Aodaruma/mcmcp/pull/88)）
- **レバーを指定したON/OFF状態に。** すでに希望の状態なら操作せず、意図せず切り替えてしまうことを防ぎます。（[Issue #75](https://github.com/Aodaruma/mcmcp/issues/75), [PR #80](https://github.com/Aodaruma/mcmcp/pull/80)）
- **時間指定・反復入力を改善。** 入力時間と、各手順の繰り返し回数を指定できます。手持ちアイテムの詳細も必要に応じて取得できます。（[Issue #34](https://github.com/Aodaruma/mcmcp/issues/34), [PR #35](https://github.com/Aodaruma/mcmcp/pull/35)）
- **プロフィール別の接続設定。** Codexの設定を分離して作成でき、別プロフィールを参照する設定も判別します。他の処理が設定を更新中でも、ゲーム画面を長時間待たせないようにしました。（[Issue #9](https://github.com/Aodaruma/mcmcp/issues/9), [PR #86](https://github.com/Aodaruma/mcmcp/pull/86)）

### 修正した不具合

- **狭い岸へのエリトラ緊急着地。** 着地して止まるまでの空間を確認し、乾いた足場を通り過ぎてしまう問題を改善しました。（[Issue #91](https://github.com/Aodaruma/mcmcp/issues/91), [PR #93](https://github.com/Aodaruma/mcmcp/pull/93)）
- **はしご付近の足場間で移動が止まる問題。** プレイヤーの実際の位置と経路のずれによって、再計画を繰り返す問題を修正しました。（[Issue #98](https://github.com/Aodaruma/mcmcp/issues/98), [PR #99](https://github.com/Aodaruma/mcmcp/pull/99)）
- **弓のエラー後に操作が残る問題。** 弓の取消・発射でエラーが起きても、操作入力を解放する処理を最後まで進めるようにしました。（[Issue #90](https://github.com/Aodaruma/mcmcp/issues/90), [PR #85](https://github.com/Aodaruma/mcmcp/pull/85)）
- **返却済みの観測を再取得できなくなる問題。** 新しい観測が届いても、直前に返された情報を有効期間内に参照できるようにしました。（[Issue #96](https://github.com/Aodaruma/mcmcp/issues/96), [PR #97](https://github.com/Aodaruma/mcmcp/pull/97)）
- **長時間処理の結果を早く返してしまう問題。** PowerShellクライアントで処理中の応答を受けたとき、指定された待機時間の上限内で結果確認を続けるようにしました。失敗・取消や途中までの結果も保持します。（[Issue #84](https://github.com/Aodaruma/mcmcp/issues/84), [PR #85](https://github.com/Aodaruma/mcmcp/pull/85)）

### ガイドと利用上の注意

- **v2向けの導入・APIガイドを更新。** 配布ZIPには本体JAR、画像付き導入ガイド、APIガイド、ライセンス、ソース取得先、チェックサムを同梱しています。（[Issue #84](https://github.com/Aodaruma/mcmcp/issues/84), [PR #94](https://github.com/Aodaruma/mcmcp/pull/94), [PR #101](https://github.com/Aodaruma/mcmcp/pull/101)）
- バッグは文書に記載した収納・検証済みMOD版が対象です。レシピ検索が不完全な場合や、検索できても自動クラフト・材料や設備の確認に未対応の場合があります。（[Issue #70](https://github.com/Aodaruma/mcmcp/issues/70), [Issue #71](https://github.com/Aodaruma/mcmcp/issues/71)）
- 緊急回復には時間・移動距離の上限があり、追加の危険が発生すると完遂できない場合があります。はしごと足場の間の移動にも、未検証の配置が残っています。（[Issue #91](https://github.com/Aodaruma/mcmcp/issues/91), [Issue #81](https://github.com/Aodaruma/mcmcp/issues/81)）
- 接続設定の診断は、AIクライアント自身の通信成功を確認するものではありません。（[Issue #9](https://github.com/Aodaruma/mcmcp/issues/9)）

詳しい検証範囲は[実機確認と残る課題](https://github.com/Aodaruma/mcmcp/blob/v0.2.0-rc.1/docs/experiments/20261115_release_rc1.md)を参照してください。
