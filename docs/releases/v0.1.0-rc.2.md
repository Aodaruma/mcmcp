## 日本語

倉庫整理のまとめ移送と、額縁の表示アイテム変更に対応したリリース候補です。コンテナ操作の結果確認と終了処理も修正しました。

**対象：Minecraft Java Edition 26.2 / NeoForge 26.2.0.59 / Java 25。** クライアント側だけに導入します。ライセンスはMPL 2.0です。

- 導入には `mcmcp-neoforge-26.2-0.1.0-rc.2.zip` をダウンロードしてください。MOD本体、画像付きREADME.md/PDF、操作ガイド、ライセンスとチェックサムを同梱しています。JARとPDFも個別に添付しています。
- チェストと樽で、同じ品目を最大14スタック・896個までまとめて出し入れできます。1クリックごとにサーバーの結果を確認し、最後にまとめて中身を読み戻します。
- 大チェストへの格納目標は3,456個まで指定できます。2,304個を超える目標が内部エラーになる不整合を修正しました。
- 通常の額縁・輝く額縁の表示品を、個別の操作で外したり入れたりできます。額縁の正面が見えていることを確認し、回転を維持します。外したアイテムの回収は別の操作です。
- 額縁の観測後にブロック更新があった場合は、同じ額縁を再確認します。描画情報が一時的に欠けた場合は、操作の制限時間内で待機します。
- 自動補充MODで手持ちが変わったときも、送信済みのコンテナ操作の読み戻しを続けます。個数が一致しない場合は未確認として扱い、操作を繰り返しません。
- チェストの終了処理がタイムアウトした後も、新しいサーバー応答などで解放を確認できれば回復します。待機中のキャンセル要求に応答し、同じエラーログの大量出力を抑えます。
- 開封前の拒否には固定の診断理由を追加しました。

実ゲームでは、複数スタックの移送、全54収納の再inspect、大チェストの2,464→2,466個の格納、額縁の取り外し・回収・再挿入を確認しました。額縁の回転と本体を維持しています。

**既知の制限：** コンテナ終了処理が最初に失敗した直接原因と、以前報告された持続的な開封前拒否の根因は未確定です。額縁も状況により実行直前の確認で拒否される場合があります。低FPS・追加MOD互換性は引き続き改善中です。落下品の専用回収が観測直後でも拒否されるケースがあり、今回の旧品回収はMCPによる移動と所持品差で確認しました。額縁操作は、同時に他のプレイヤーが変更する場合の競合を完全には防げません。

ローカル検証：unit 1,194件、harness 13件、admin bridge 21件の計1,228件と、配布ツール3件が成功。JARの開発用コード混入検査とビルドも通過しています。詳しい条件と結果は[検証記録](https://github.com/Aodaruma/mcmcp/tree/v0.1.0-rc.2/docs/experiments)を参照してください。

## English

This release candidate adds bounded batch transfers for warehouse organization and item-frame display changes. It also improves container readback and cleanup recovery.

**Requires Minecraft Java Edition 26.2, NeoForge 26.2.0.59, and Java 25.** Install on the client only. Licensed under MPL 2.0.

- Download `mcmcp-neoforge-26.2-0.1.0-rc.2.zip` for the mod, illustrated README in Markdown/PDF, action guide, licenses, and checksums. The JAR and PDF are also attached separately. The illustrated guide is in Japanese.
- Move up to 14 stacks or 896 items of one item type in a chest or barrel operation. Each click requires server confirmation, followed by one final readback for the batch.
- Large-chest destination goals support up to 3,456 items, fixing an internal error for goals above 2,304.
- Remove or insert a displayed item in a visible vanilla item frame or glow item frame, using separate operations that preserve rotation. Collecting the removed item is a separate action.
- Rechecks the same frame when a block update invalidates its observation, and waits within the original action deadlines when current renderer evidence is temporarily unavailable.
- Container readback continues when an automatic refill mod changes the held item after dispatch. Unmatched item counts remain unknown and do not trigger a blind retry.
- Timed-out container cleanup can recover when new server evidence proves release. Cancellation requests remain responsive during cleanup, and repeated identical error logs are suppressed.
- Fixed diagnostic reasons help identify container preflight rejections.

In-game checks covered multiple-stack transfers, all 54 storage inspections, a large chest increasing from 2,464 to 2,466 items, and one item-frame remove/collect/insert round trip with the frame body and rotation preserved.

**Known limitations:** The original trigger of the cleanup failure and the root cause of a previously reported persistent preflight rejection remain undetermined. Frame actions can still be rejected at the final admission check in some situations. Low-FPS stability and compatibility with additional mods remain in progress. Dedicated dropped-item collection can reject fresh observations; the round-trip collection was verified through MCP navigation and inventory changes. Item-frame interactions cannot fully prevent races with another player changing the same frame.

Local validation: all 1,228 Java tests passed (1,194 unit, 13 harness, 21 admin bridge), plus three release-tool tests. The build and production JAR isolation check also passed. See the [verification records](https://github.com/Aodaruma/mcmcp/tree/v0.1.0-rc.2/docs/experiments) for conditions and results.
