## コンテナ回帰

許可済みのリモート隔離Dockerに検証専用fixture-adminを導入した。
追加allowlistはVanilla barrelとwaxed copper chestだけで、変更範囲・数量上限・宣言container・selector等の制約を維持する。
fixture準備とUIでのMCP ONはAction開始前だけに行い、各run中は公開5 Toolを既存transportで呼ぶ。
これは決定的な機能回帰試験であり、freshモデルのMCP-only自律完遂評価や常用の登録済み接続の認証試験ではない。
FPS保存値60、VSync無効、実効CPU制限なし（`cpu.max=max 100000`）。

| run | 内容 | 判定 |
| --- | --- | --- |
| run01 normal | 通常chestを単独inspect、snow block 14スタック896個をtake、空を再inspect、barrelへ896個storeしてinspect。銅double chestは47+27個のblack woolをinspect→take→空をinspect→74個store→inspect | 10 Actionすべて成功。移送effectは全てCONFIRMED、UNKNOWN 0 |
| run02 partial（初期fixture） | 47+64個を用意したが、double chestのmenuは想定と逆の半分から読み、最初に64個移送 | 想定47個との不一致でgate失敗。製品の部分成功47残/64移送の記録は整合。成功runへ数えない |
| run03 partial（fixture修正後） | menuで先に読む半分へ47個を配置。上限74でtakeすると47個だけ成功し、残り64個のwhole stackが上限に収まらず停止。fresh inspect後、新Actionで64個を追加取得し、111個をstoreしてinspect | 6 Action中、意図した部分失敗1件と成功5件。確認済み総量・再観測要求・残量・最終111個が一致、UNKNOWN 0 |

run02の失敗Actionを再送せず、terminalとREADYを確認後にfixtureを再適用した。
run03は同じ製品JAR・gateのまま、fixtureの左右の個数だけを交換した。
partialは`SERVER_DENIED_OR_DESYNC / transfer_batch_goal_not_reached`、`has_confirmed_effects=true`、`resume_requires_reobservation=true`を必須にした。
inspect結果は同じAction ID、正しいtarget、非truncated、次pageなし、品目合計を照合する。
transferはCONFIRMED effectの量と、実所持の増減の両方を検査する。
全runはfinallyで全Action terminalと公開stateのREADYを確認した。公開Toolは入力ownerを直接露出しないため、owner値の直接確認とは表現しない。

#2の以前のコメントは、旧登録接続のAuth requiredを理由に、16個のhelper試験を暫定扱いとしていた。
今回その常用接続を再認証したとは主張しない。公開可否は、現行版付きJARで元のhotbar充填条件まで再現した製品回帰として判断する。
登録接続・freshモデル評価の合格へ読み替えず、旧接続の認証確認を製品開封修正の合否から分離する。
未統合の#21 / #34およびPR #26 / #35はこの公開対象外で、確認ラベルを残す。

## 建築の証拠と限界

[建材](20260914_vanilla_construction_materials.md)、[端設置](20260914_sneak_edge_extension.md)、
[進捗保存・補充・別プロセスでの再開](20260914_construction_progress.md)、
[水中移動](20260914_water_navigation.md)、[最終床lease検査](20260915_floor_lease_guard.md)を照合した。
最終床lease版では正常な端設置8回、取消し2回、外部pauseによる失効停止・復旧を確認済み。
rc.3の全製品class一致は、同じ実装を配布する根拠になるが、全条件の再実機試験を意味しない。

利用者から地上絵の完成報告を受けた。公開MCPの施工操作と外部runner・進捗台帳を用いた現場の運用実績として記録する。
第三者による完成画素の全数監査、QRの読取結果、freshモデルの無介入完遂を今回新たに認定するものではない。
全Vanilla特殊ブロック、MOD追加ブロック、任意の水域、CPU停滞の根因解消、未知Actionの自動再送は対応範囲に含めない。

## ソース・配布検証

Java通常1,304件、harness 13件、admin bridge 27件、isolation/buildが成功した。
配布ツール3件、Python transport 14件、施工台帳・回復・保存競合・観測とcapabilityの模擬試験が成功した。

Markdown/CSSからrc.3のZIPと8ページPDFを生成し、全ページを画像で確認した。
独立Codex CLIレビューの対象SHA・最終差分・結論とCI結果はリリースPRへ記録する。
CLIの読み取りbackendが欠けていたため、差分と直接参照コードを入力に同封した静的レビューを使用し、失敗した読み取り試行をレビュー成功には数えていない。
