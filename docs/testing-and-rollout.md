# テストと段階導入

## 原則

メインの「くらふとぶ！」インスタンスを直接変更しません。Prism Launcherで複製した検証用インスタンスにだけMODを追加し、各ゲートを順番に通します。

## Phase 0: 設計

- [x] 実環境のMinecraft / NeoForge / Java / MODバージョン確認
- [x] サーバー接続とSimple Voice Chat接続のbaseline確認
- [x] MCP、NeoForge、Voice Chatの実現性調査
- [x] 安全境界、MCP API、導入ゲートの文書化

## Phase 1: 読み取り専用PoC

- NeoForgeクライアント専用MODの最小ビルド
- loopback MCPサーバー、Origin検証、認証、rate limit
- `get_status`、`get_snapshot`、`emergency_stop`
- クライアントスレッドdispatchとtimeout
- タイトル、ローカルワールド、切断、終了の各ライフサイクル試験
- 既存ログbaselineとの差分検査

合格条件:

- LANからポートへ接続できない
- 不正Origin、認証なし、巨大入力を拒否できる
- 30分のアイドル・ワールド出入りでクラッシュ、thread leak、tick悪化がない
- 外部クライアントからゲーム状態へ直接触るコードパスがない

## Phase 2: stationary_break

- 最大60秒から開始し、上限300秒
- クロスヘア対象、リーチ、GUI、フォーカス、体力、敵対mob、進捗を毎tick監視
- 2秒以下の攻撃リース
- Voice Chatミュート・復元
- 緊急停止、実入力、切断、死亡、例外の全経路で入力解放

合格条件:

- 100回の開始・停止で保持入力が残らない
- 強制切断、Alt+Tab、Esc、死亡、Voice Chat切断の各試験で1tick相当を目標に停止する
- ミュート前状態がtrue/falseの両方で正しく扱え、手動変更を上書きしない
- 通常プレイヤーと同じ採掘速度・リーチ・サーバー判定を通る

## Phase 3: マルチプレイ互換性試験

事前確認:

- 利用者が接続先のルールとクライアント自動化の扱いを確認
- 作業場所、対象ブロック、最大時間をローカル設定で制限
- ログ採取と即時削除手順を準備

最初は1分、5分、15分と段階的に延ばし、サーバー負荷・アンチチート・他プレイヤーへの影響を確認します。問題があればMODを検証インスタンスから外すだけでrollbackします。

## 将来候補

1. 直線移動と安全停止
2. 単純な畑一列の収穫・植え直し
3. 限定されたコンテナ操作
4. 建築補助
5. Baritone等の経路探索adapter

Baritoneは大幅に能力面と監査面を増やすため、PoCには含めません。導入する場合も可視・到達可能情報だけを使う専用ポリシーと、環境ごとの明示的なユーザー設定が必要です。

## リリース判定

次のいずれかが未達なら、その環境での能動自動化はNO-GOです。

- 全停止経路の自動テスト
- MCPのloopback/auth/origin試験
- Voice Chatのfail-closedと状態復元試験
- 対象Modpackの起動・接続・30分稼働試験
- クラッシュ時に入力がOSレベルで残らないことの確認
