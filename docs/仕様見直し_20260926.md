# 仕様見直し用メモ（2026-09-26）

本書は配布中の仕様、候補実装、未対応を混同しないための確認表である。公開Toolの完全なschemaは[MCP catalog](MCMCP_MCP_Tool_Catalog.json)、操作契約は[設計仕様書](Minecraft_MCP_NeoForge_設計仕様書.md)を正本とする。

| 対象 | 配布版mainの仕様 | 今回の候補・合意 | 残る確認 |
| --- | --- | --- | --- |
| 公開Tool | state / observation / start / get / cancelの5本 | 5本を維持し、収納操作は既存DSLへ追加 | 実際の接続先のcatalog更新確認 |
| MOD収納 | 手動で開いた既知menuから通常stackを全量take | 開閉・個体選択と、共通Menuの数量計画・同期・照合を分離。所持/胸/offhandの対応バッグをinspect/take/store | Docker実機、未初期化/入れ子/linked/world MOD収納、追加provider |
| 拡張stack | 既存whole-stack経路では除外 | 収納容量とcursor上限を分け、既存の14click計画を利用 | 自動補充やupgradeを含む実機境界 |
| はしご | 観測入口から上下4段、接地landingだけを公開目的地とする | 全体高さの固定上限なし。観測済み区間を進む→途中SHIFT停止→再観測→再開。上端/途中の横・対岸へ通常乗移り | #81。ジャンプ越えは今回含めない。入力保持の所有権とOFF/取消の仕様・試験 |
| 実行停止 | 有限Action、未確認操作の再送なし、未解放時はlock | 収納でも確認済みprefixとUNKNOWN末尾を別々に記録 | 同期欠落・遅い開封・手動介入時の実機確認 |

収納では`storage_id`で同じバッグを追い、毎Actionは新しい`operation_ref`を使う。内容は実際に開いた後の履歴として返す。未開封の中身や任意NBTは読み出さない。対応する新MODを追加するときも数量移送処理は複製せず、開き方・個体識別・slot容量・同期差分をproviderへ実装する。

候補ビルド、単体試験合格、実機合格、main統合、Releaseは別の状態で管理する。ユーザーの追加指示があるまでPRまでに留める。
